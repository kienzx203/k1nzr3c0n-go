# Vulnerability verification knowledge (appsec review)

For each candidate, find its class below and apply the VERIFY criteria to decide CONFIRMED
vs FALSE-POSITIVE vs LIKELY (suspected) before reporting. These are the specialist checks
that were previously the per-vulnerability agents — now one skill for the reviewer.

### aipent (`aipent`)
- Use these pages as the attack/review reference for this domain. When this agent
  reviews a target, CONFIRM a finding only with concrete evidence from the code/config;
  treat name-only or version-only signals as LIKELY until verified.

### airflow (`airflow`)
- CONFIRMED when: the reviewed IaC / config / manifest / pipeline grants the risky
  exposure above — public access, wildcard principal/role, disabled auth or MFA, an
  over-broad scope/permission, a plaintext secret, or an unpinned/untrusted step — with
  no compensating control.
- FALSE POSITIVE when: least privilege is enforced, access is restricted/allow-listed,
  auth/MFA is on, secrets live in a vault/OIDC, steps are pinned, or the resource is
  intentionally and safely public.
- LIKELY when: the risky pattern is present but the surrounding guardrail (SCP, policy
  boundary, network rule, branch protection) is not visible in the reviewed files.

### cmdi (`cmdi`)
- CONFIRMED when: tainted data is part of a **shell command string** (`sh -c`, `cmd /c`,
  backticks, `shell=True`, a `system()`-family call) with no allow-list.
- FALSE POSITIVE when: passed as a **separate argv element to exec WITHOUT a shell** and the
  program name is constant (classic argv exec is injection-safe), or strictly allow-listed.
- LIKELY when: argv exec but the tainted value could be an **option/flag** (arg injection), or
  shell usage is not fully visible.

_Remediation:_ Use argv-array exec without a shell; allow-list the binary + args; reject values starting with `-`;

### deserial (`deserial`)
- CONFIRMED when: untrusted bytes (body/cookie/param/file/queue) hit a **native/polymorphic
  deserializer** with no class allow-list or safe-mode.
- FALSE POSITIVE when: a data-only parser is used (`JSON.parse`, `yaml.safe_load`, Jackson
  without default typing), or an `ObjectInputFilter`/class allow-list is enforced, or input is
  signed+verified before deserializing.
- LIKELY when: the deserializer is risky but the source's trust level or filtering is unclear.

_Remediation:_ Prefer JSON data binding without polymorphic typing; enforce class allow-lists; `safe_load`;
